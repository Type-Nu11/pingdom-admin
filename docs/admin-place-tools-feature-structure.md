# 관리자 장소 이벤트·중복 후보·병합 파일 이동 (#333)

기준: develop `c3b6e02e4dede7be2414bff643f8806d7b7550a5` (#345 병합).
브랜치: `refactor/admin-place-tools-structure-333`.

## 파일 소유권

| 기능 | 폴더 | 이동 범위 |
| --- | --- | --- |
| 기간형 이벤트 | `src/features/admin/placeEvents` | 화면·훅·API·타입 4개 |
| 중복 후보 검토 및 병합·복구 | `src/features/admin/placeMerge` | 화면 2개·스타일·훅 2개·API·타입 7개 |

- 세 화면의 기존 URL·개별 지연 로딩·관리자 접근 권한·Provider 범위를 유지한다.
- 대시보드와 상단 알림의 처리 필요 업무는 기존 후보 및 중복 그룹 조회 함수를
  새 위치에서 호출한다. 후보 비교의 장소 상세 조회는 장소 관리 API를 계속 사용한다.
- `PlaceMergePage.styles.ts`는 이벤트·검증 등 다른 화면과 공용 컴포넌트도
  사용한다. 원본 스타일 하나만 이동하고 기존 의존 관계를 연결한다. 스타일 소유권의
  추가 분리나 외형 통일은 이번 범위가 아니다.
- 옛 위치에 호환 재내보내기나 화면을 함께 불러오는 모듈을 만들지 않는다.
- 계약표 263행 중 17행은 `frontend_target`의 파일 경로만 변경했다. 마지막 한 행은
  중복 후보 화면이 호출하는 장소 상세 조회다. URL·payload·스키마·권한·검증일은 유지한다.

## 검증 범위

- 기준의 소스 315개를 현재 경로로 정규화해 코드 본문과 실제 import 대상을 비교했다.
  API 근거 202개도 파일 위치 외에 method/path/function/callers가 동일했다.
- 단위 검사에서 11개 파일의 단일 위치와 이동 전 본문·참조 대상을 확인한다.
  이전 구조 검사의 기준값을 바꾼 항목은 스타일 사용처 경로와 API 위치뿐이다.
- 새 브라우저 검사는 실제 라우터·화면·훅에 합성 API를 연결한다. 1366×768 및
  390×844에서 이벤트 날짜 팝업 포커스 복귀, 미저장 입력 유지/버리기, 공개/취소 확인,
  중복 후보 페이지 이동/선택 해제, 판정 사유와 병합 확인 체크, 병합/복구 확인창 취소를
  변경 전후 모두 검증했다. 운영 요청이나 합성 데이터 변경 요청은 보내지 않았다.
- 기존 장소 선택기 브라우저 검사도 세 화면 크기에서 변경 전후 통과했다. 캡처 12개 중
  10개는 바이트까지 일치했다. 캡처 전체가 동일하다고 주장하지 않는다.
- 별도 `unsaved-changes.mjs`는 이벤트 확인 이후 장소 정보 증빙 등록의 설명 입력에서
  기준과 변경 후 모두 timeout이 발생했다. 검사를 완화하거나 해당 화면을 수정하지 않았다.
