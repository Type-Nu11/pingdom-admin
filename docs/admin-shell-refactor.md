## PR #338 후속: 장소 신고 검토 검사의 인증 전환

최초 HEAD `567a341`의 원격 CI `42976852920`은 Docker 이미지·lint·build·단위 검사는
성공했지만 `place-dispute-review.mjs`에서 401 처리 후 계정 102로 전환하고 빈 목록을
기다리는 단계가 30초 제한으로 실패했다. 로컬 단독 재실행은 통과했으므로 원격 실패
당시의 정확한 응답 순서는 기존 로그만으로 단정하지 않는다.

후속 진단에서는 원래 테스트용 인증 구성이 로그아웃해도 보호 페이지를 유지하는
문제를 별도로 재현했다. 계정 101의 401 → 로그아웃 → 사용자 null 반영 → 보호 API
재조회 → 추가 401 → 두 번째 로그아웃 호출 순서가 기록됐다. 새로 추가한
`logged-out fixture must not keep fetching a protected page` 검사는 수정 전
`1 !== 0`, `clears=2`로 실패했다. 이는 원래 CI의 30초 timeout 자체를 결정적으로
재현했다는 뜻이 아니라, 검사 구성의 인증 수명 문제를 실패→성공으로 검증한 것이다.

수정 범위는 두 브라우저 검사 파일과 이 문서뿐이며 실제 앱 인증·조회·UI 코드는
변경하지 않는다.

  재실행에 따라 5~7장만 동일했으며, 관찰한 나머지 차이는 페이지 이동 버튼 영역이었다.
  이를 모든 화면의 픽셀 일치로 보고하지 않는다. 실제 콘텐츠·필터·페이지 이동·심사·
  실패 복구와 좁은 화면 넘침 검사는 변경 전후 모두 통과했다.
- 별도 검사 세 개는 변경 전후 같은 지점에서 실패했다. 이 단계에서 수정/완화하지 않았다:
  - `navigation.mjs:92`: 390px 키보드 이동 후 스크롤 `1683 !== 1684`.
  - `admin-naver-map.mjs:73`: 연속 확대 후 zoom 값 대기 10초 timeout.
  - `merchant-naver-map.mjs:137`: 합성 업체 검색 결과 버튼 대기 10초 timeout.
  이는 각 실패의 원인을 확정하거나 지도 전체 QA를 완료했다는 뜻이 아니다.
- 합성 Chromium/SDK·로컬 검사 결과다. 실제 네이버 SDK/인증 서버 읽기, 운영 쓰기,
  Safari/Firefox·실기기·운영 폰트·배포 검증은 수행하지 않았다.
- 커밋·푸시·PR·원격 CI는 별도 승인과 실제 결과 확인이 필요하다. #333 전체 완료나
  운영 배포 완료로 처리하지 않는다.

## 3단계 첫 묶음: 장소 관리 파일 이동

장소 관리 소유 파일은 `src/features/admin/places/`로 이동한다. 위 1·2단계의 기준 커밋과
옛 경로는 당시 검증 기록으로 보존한다. 현재 소유권·외부 연결·이동 경로·검증과 미해결
검사의 상세는 [장소 관리 기능 파일 정리](admin-place-feature-structure.md)를 참조한다.
