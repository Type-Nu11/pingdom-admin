## PR #338 후속: 장소 신고 검토 검사의 인증 전환

최초 HEAD `567a341`의 원격 CI `42976852920`은 Docker 이미지·lint·build·단위 검사는
성공했지만 `place-dispute-review.mjs`에서 401 처리 후 계정 102로 전환하고 빈 목록을
기다리는 단계가 30초 제한으로 실패했다. 로컬 단독 재실행은 통과했으므로 원격 실패
당시의 정확한 응답 순서는 기존 로그만으로 단정하지 않는다.

후속 진단에서는 원래 테스트용 인증 구성이 로그아웃해도 보호 페이지를 유지하는
문제를 별도로 재현했다. 계정 101의 401 → 로그아웃 → 사용자 null 반영 → 보호 API
재조회 → 추가 401 → 두 번째 로그아웃 호출 순서가 기록됐다. 새로 추가한
`logged-out fixture must not keep fetching a protected page` 검사는 수정 전
`1 !== 0`, `clears=2`로 실패했다. 이는 원래 CI의 30초 timeout 자체를 결정적으로
재현했다는 뜻이 아니라, 검사 구성의 인증 수명 문제를 실패→성공으로 검증한 것이다.

수정 범위는 두 브라우저 검사 파일과 이 문서뿐이며 실제 앱 인증·조회·UI 코드는
변경하지 않는다.

- 테스트의 인증 콜백을 고정하고 로그아웃 시 보호 페이지를 내리도록 한다.
  실제 인증 서버/알림 Provider를 사용하지 않으면서 보호 라우트의 페이지 수명을 모사한다.
- 단순 `clearAuth` 호출 횟수가 아니라 로그아웃 화면·계정 반영·요청 종료 상태를
  확인한 뒤 다음 계정으로 전환한다. 로그아웃 중 보호 조회 0회와 해제 1회를 검사한다.
- 이전 계정의 조회를 401 상태로 보류한 채 새 계정 103의 목록 조회를 완료한 후,
  이전 응답을 해제해 새 계정이 로그아웃되거나 빈 목록이 사라지지 않는지 확인한다.
- 실패 시 화면 크기·합성 계정 ID·제한된 요청 순서·상태 코드·합성 화면 텍스트와
  스크린샷을 남긴다. 요청 본문·토큰·쿼리 값은 진단 기록에 넣지 않는다.
- `PINGDOM_QA_CPU_RATE=4 node tests/browser/place-dispute-review.mjs`로 느린 CPU 조건을
  검사할 수 있다(기본값 1, 허용 1~8). CI 기본 속도와 30초 대기 제한은 바꾸지 않는다.
- 오류 수집·실제 외부 요청 차단·기존 입력 보존/권한/저장 재시도/계정 변경 검사와
