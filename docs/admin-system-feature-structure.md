# 관리자 시스템 메뉴 기능별 파일 이동 (#333)

기준: develop `775649279367682a23560a618ba6b1980e4ac83e` (커뮤니티 PR #344 병합).
작업 브랜치: `refactor/admin-system-structure-333`.

## 소유권

| 화면 | 기능 폴더 | 범위 |
| --- | --- | --- |
| 데이터 품질 | `src/features/admin/dataQuality` | 화면·조회 훅·API·타입 4개 |
| 알림 발송 현황 | `src/features/admin/notificationOperations` | 화면·운영 훅·표시 라벨 3개 |
| 운영 이력 | `src/features/admin/operationHistory` | 화면·전용 스타일·조회 훅·API·타입 5개 |
| 미연결 파일 관리 | `src/features/admin/s3Orphans` | 화면·리포트 훅·API·타입·리포트 상태 판별 5개 |

- 17개 파일의 소유 위치와 import 경로만 바꾼다. URL·개별 lazy import·관리자 권한,
  hook 상태/요청 수명·알림 Provider 수명·JSX·문구·스타일을 유지한다.
- 상단 알림과 운영 화면이 함께 사용하는 알림 API·타입은 기존 위치에 남긴다.
  알림 Provider, Context, 버튼, 대시보드 연동도 그대로 둔다.
- 운영 이력과 알림 화면이 함께 쓰는 `adminAuditPresentation`은 옮기지 않는다.
  기존 장소 병합/검증 스타일 참조와 관리자 공통 레이아웃도 그대로 유지한다.
- 운영 이력의 감사/개인정보 탭·필터, 데이터 품질 페이지 처리, 알림 재처리 대상/중복
  제출 방지, 저장소 리포트 상태와 선택·리포트 ID 확인 조건을 바꾸지 않는다.
- 지도 및 장소 조회 내부 리팩토링 #337, 보류 중인 지도 기능 #331, 버튼/여백/공통
  디자인 및 큰 파일의 내부 책임 분리는 범위 밖이다. 운영 데이터 쓰기·배포는 하지 않는다.

## 구조와 계약 검증

- 고정 기준에서 생성한 fixture로 17개 파일의 코드 본문 및 import 대상, 배치,
  외부 참조, 라우터 접근 경계, 옛 경로와 공통 모듈 보존을 검사한다. 신규 단위 24개.
  단위 실행은 Git 과거 이력에 의존하지 않는다.
- 별도 기준 체크아웃과 315개 소스의 실제 import 대상을 정규화해 비교했다.
  경로 이외 소스 텍스트가 동일하다. API 근거 202개의 method/path/function/callers도
  명시한 이동을 적용하면 동일하다.
- 이전 두 구조 검사 fixture의 API 인벤토리 기대 해시와 장소 검증 스타일 소비자 경로는
  이 파일 이동만 반영했다. 기존 원본 기대값을 기준 체크아웃과 먼저 대조했으며 이전 소스
  코드 해시 및 assertion은 바꾸지 않았다.
- 웹 계약표 263행 중 14행의 `frontend_target`만 갱신했다. 공개 문서에 없는 데이터
  품질 API의 근거 목록도 동일한 위치 변경만 반영한다. OpenAPI 원본과 구현 상태, 요청/
  응답 형식·권한·검증 날짜는 갱신하지 않는다.
- 별도 과거 회귀 스크립트의 #156 검사는 Git의 옛 경로로 원본을 읽되, 임시 체크아웃의
  새 경로에 의존 경로를 보정하여 적용한다. 제품 코드에 호환용 재내보내기를 만들지 않는다.

## 재현 방법

```sh
npm test
npm run lint
npm run build
npm run check:api-matrix
npm run test:release-browser
git diff --check
```

릴리스 브라우저 묶음에 운영 이력 및 알림 발송 현황, 데이터 품질,
미연결 파일 확인 화면이 포함된다. 실제 컴포넌트/훅과 합성 API를 사용한다.
미연결 파일 테스트는 선택 전, 빈 ID/다른 ID, 일치하는 ID의 확인 버튼 상태 및
취소를 1920×1080·1366×768·390×844에서 확인하고 DELETE를 전송하지 않는다.
실서버 알림 재처리·파일 삭제, 운영 데이터/지도 SDK·실기기 검증은 수행하지 않는다.

## 확인 결과

- 기준 checkout 단위 1,249개, 변경 후 단위 1,273개 통과. 양쪽 lint·TypeScript 포함
  빌드·계약표 검사가 통과했다.
- 파일 이동·기존 경로 수정만 포함한 첫 커밋 예정 스냅샷을 별도 Git 체크아웃에서 검증해
  기존 단위 1,249개가 통과했다.
- 변경 전후 릴리스 브라우저 각 25개 스위트 통과. 데이터 품질의 조회/필터·페이지 이동·
  상세 선택·요청 실패 후 재시도·권한 오류 및 PC/좁은 화면 레이아웃을 확인했다.
- 기존 운영 이력/알림 검사에서 필터의 API 코드, 드롭다운 노출, 재처리 대상 정보·
  확인창 취소를 비교했다. 알림 훅의 합성 재처리 검사도 대상과 중복 제출 방지를 검증한다.
- 미연결 파일 화면은 기존/변경 코드 모두 새 확인 절차 검사를 통과했다. 3개 뷰포트의
  확인창 열기 전 캡처는 바이트까지 동일했다. 390px에서 기존 ‘삭제 후보’ 제목과 설명의
  너비가 좁아 글자 단위로 줄바꿈되는 문제는 이번 구조 이동에서 변경하지 않았다.
- 운영 이력/알림 캡처 15개 중 10개는 바이트까지 동일했고 나머지 5개는 드롭다운
  및 알림 본문의 국소 영역에 차이가 있었다. 픽셀 완전 일치 또는 전체 접근성 검증을
  주장하지 않는다.
- Git 이력을 사용하는 별도 과거 회귀 스크립트에서 #156은 현재 코드 통과 및 옛 코드의
  의도된 assertion 실패를 확인했다. 전체 스크립트는 기존 #148·#150·#153 검사에
  실패하며, 기준 checkout과 변경 소스에서 동일하게 재현됐다. 릴리스 브라우저 묶음과는 별개다.
