# 관리자 대상 검색 및 장소 상세 연결 (#170)

## 적용 범위

- 예약 신청 심사: 장소 이름/주소 검색 후 정확한 장소 ID를 선택한다. 직접 ID 입력도 유지한다.
- 사용자 역할: 관리자 사용자명 검색 후 사용자 ID로 역할을 조회한다. 일반 사용자 전체 검색이 아니다.
- 장소 신청 심사의 연결 장소와 예약 상세의 장소는 `/places?placeId={id}`로 연결한다.
- 장소 목록에 없는 ID도 상세 조회하며, 새로고침과 뒤로가기는 URL의 선택 대상을 복원한다.

## API 계약

2026-09-16 배포 OpenAPI 및 서버 컨트롤러 확인 기준이다.

| 대상 | API | 검색 및 응답 |
| --- | --- | --- |
| 장소 | `GET /admin/places` | `keyword`, 1부터 시작하는 `page`, `limit=10`. 이름/등록자 ID/주소 검색. 목록의 이름, 주소, ID로 구분 |
| 역할 부여 대상 | `GET /admin/users/role-targets` | `keyword`, `page`, `limit=10`. 관리자 사용자명 부분 일치, 빈 검색어는 허용된 전체 대상. `users[{userId, username}]`, `totalCount`, `totalPages`, `hasNext` |
| 사용자 역할 | `GET /admin/users/{userId}/roles` | 선택한 ID로 기존 역할 조회 흐름 사용 |
| 장소 상세 | `GET /admin/places/{placeId}` | 현재 목록과 독립적으로 대상 조회 |

사용자 검색은 실명 검색이 아니며 이메일/전화번호를 조회하거나 표시하지 않는다. 역할 변경의 기존 사유 입력과 확인 절차를 유지한다.

## 상태 처리

- 검색 실행 시 페이지를 1로 초기화한다. 동일 이름은 ID와 장소 주소로 구분한다.
- 이전 검색의 늦은 응답은 새 검색 결과를 덮어쓰지 않는다.
- 조회 실패와 결과 없음은 별도로 표시하며 실패한 검색을 재시도할 수 있다.
- 대상 변경 시 이전 역할/장소 상세와 열린 작업 대화상자를 정리한다.
- 역할 변경 중에는 대상 변경을 막는다.
- 유효하지 않은 장소 ID는 상세 링크를 만들지 않는다.

## 검증

- `npm test`: 검색 경합, 페이지 초기화, 오류/빈 결과, 어댑터 계약, 역할 대상 변경 검증.
- `npm run test:admin-target-browser`: 합성 API로 1280px/390px 화면의 검색 선택, 정확한 ID 요청, 목록 밖 장소 상세, 새로고침/뒤로가기 검증.
- `npm run test:place-inspector-browser`: 기존 장소 상세 화면 회귀 검증.
- 실제 인증 서버의 계정별 권한 및 실제 지도 SDK 동작은 합성 브라우저 테스트 범위에 포함하지 않는다.
