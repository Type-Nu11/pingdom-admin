# 증빙 미리보기 브라우저 검증

관련 이슈: #166

## 실행

```sh
npm ci
npx playwright install chromium
npm run test:attachment-browser
```

실제 장소 신청 심사 페이지와 미리보기 컴포넌트를 Chromium에서 실행한다.
별도 테스트 진입점은 운영 번들에 포함하지 않는다. Vite는 빈 로컬 포트를 사용하고
검증 성공·실패 시 브라우저와 함께 종료된다. 화면 캡처와 독립 Vite 캐시는 출력에 표시한
시스템 임시 디렉터리에 남긴다. 기존 개발 서버 포트를 변경하지 않는다.

API는 Axios 테스트 어댑터로 대체한다. 로컬 테스트 자원과 기존 UI 폰트 CDN만 허용하고,
실제 API 요청은 차단한다. 파일·상점·신청자·계정은 모두 합성 데이터다.
실제 운영 증빙이나 로그인 토큰은 필요하지 않다.

## 확인 범위

- 1280×800, 390×800에서 실제 심사 상세의 미리보기 버튼으로 진입
- 공백 없는 긴 파일명 줄바꿈과 모달 내부 가로 넘침 검사
- 합성 PNG 디코딩 및 한글 2페이지 PDF 표시, canvas 비어 있지 않음 검사
- 이미지 확대·축소 및 50%/200% 경계의 포커스 유지
- Tab/Shift+Tab 순환, Escape 닫기 및 열기 버튼으로 포커스 복귀
- PDF 첫·마지막 페이지 이동과 키보드 포커스 유지
- 키보드로 PNG·PDF 다운로드 이벤트 및 파일명 확인
- 손상 이미지·손상 PDF·권한 거부·미지원 파일의 안내 확인
- 처리되지 않은 브라우저 JavaScript 예외 없음

기존 `attachment-preview.test.mjs`의 늦은 응답 차단과 object URL 정리,
`pdf-cmap.test.mjs`의 한글 CMap 검증도 전체 테스트에서 유지한다.

## 발견 및 수정

PDF 마지막 페이지 버튼이 비활성화될 때 포커스가 문서 본문으로 빠져
Escape가 모달로 전달되지 않았다. 페이지 이동 시 PDF 영역으로 포커스를 이동한다.
확대·축소 한계에서도 버튼 비활성화로 포커스를 잃지 않도록 도구 영역으로 이동한다.
공백 없는 파일명은 공통 모달 설명에서 줄바꿈하도록 보완했다.

## 결과 및 한계

2026-09-15: 두 화면 크기의 브라우저 시나리오 통과. 이미지와 한글 PDF 화면 캡처를
직접 확인했다. 전체 자동 테스트 275개 및 lint/build를 통과했다.

실서버 권한·증빙 전달 및 운영 배포 검증은 아니다. Safari/Firefox와 실제 보조공학
기기의 사용성 검증은 수행하지 않았다. 이번 결과만으로 #108의 실서버 전환 게이트나
운영 배포 완료를 표시하지 않는다.
