# 재로그인 안내와 작업 화면 복귀 (#241)

## 동작

- 기존 갱신 요청과 요청별 세션 검사, 동시 갱신 공유, 계정 전환 직렬화를 유지한다.
- 인증 정리가 필요한 401·갱신 인증 거절은 인증 만료/무효 안내를, 갱신 토큰 사용자 불일치는 세션 변경 안내를 남긴다. 일반 403·네트워크·타임아웃·5xx는 세션을 지우지 않는다.
- 인증을 정리하기 전에 현재 사용자의 ID·역할과 안전한 내부 복귀 경로를 탭별 sessionStorage에 기록한다. 재로그인 정보의 유효기간은 30분이며 로그인 후 한 번 사용하고 지운다.
- 같은 ID·역할로 로그인했을 때만 상세 대상을 복원한다. 계정·역할이 다르면 역할별 홈으로 이동한다. 기존 미저장 폼은 복원하지 않는다.
- 허용된 실제 라우트와 조회 조건만 보관한다. page, 장소 관리·증빙의 placeId, 정보 검증·방문자·Scout·Trust Score의 허용된 tab을 지원한다. 검색어·신청자 ID·작성 내용·임의 query·hash는 보관하지 않는다.
- 미로그인 직접 진입에서는 상세 대상 ID를 제외한 안전한 화면 경로만 기록한다. 인증 정보가 없는 상태에서 이전 계정을 추측하지 않는다.
- 명시적 로그아웃은 복귀 대상과 사유를 지운다. 대상 없는 로그아웃 표식을 남겨 보호 라우트가 즉시 guest 복귀 대상을 재생성하지 않도록 한다.
- 다른 탭의 계정 변경은 이전 복귀 정보를 지운다. 다른 탭의 인증 해제는 세션 변경 안내를 남기며 상세 대상과 이전 계정 ID를 보관하지 않는다.
- 로그인 사유는 로그인 실패 오류와 분리해서 표시한다. 로그인 역할을 바꾸면 기존 복귀 정보와 사유를 해제한다.
- 저장소가 차단되면 인증 처리를 계속하고 역할별 홈으로 이동한다. 메모리 안내가 가능한 동안은 안내하되 새로고침 후 저장소 없이 복구하지 않는다.

## 검증

- `tests/auth-return.test.mjs`: 경로·역할 검증, 외부/알 수 없는 경로 거절, query 제거, 만료/변조/미래 일시, 다른 계정·역할, 저장소 차단, 반복 정리, StrictMode 효과 재실행, guest 이동, 로그아웃, 원격 계정 변경·인증 해제.
- 기존 `auth-session`, `auth-error-policy`, `cross-tab-auth` 테스트로 갱신 성공·실패, 동시 요청, 취소, 지연 응답의 기존 방어를 검증한다.
- `node tests/browser/auth-return.mjs`: 실제 AuthProvider·보호 라우트·로그인 화면과 합성 Axios 어댑터로 Chromium 1920×1080, 1366×768, 390×844에서 갱신 성공 시 입력 유지, 403·갱신 503·타임아웃 세션 유지, 인증 실패 안내, 잘못된 로그인 오류 분리, 로그인 새로고침, 같은 계정 복귀, 다른 계정 홈 이동, 명시적 로그아웃, Enter 제출, 가로 넘침을 확인한다.
- 스크린샷은 테스트가 출력하는 임시 경로에 저장한다. 로그인·갱신·로그아웃은 모두 모의 응답이며 실제 업무 mutation과 외부 업무 네트워크 요청은 차단한다.
- 실서버/실계정 인증, 실제 다중 탭 쿠키 전환, 배포 QA, Safari/Firefox는 수행하지 않는다. 다중 탭 동작은 storage event를 이용한 자동 테스트로 검증하며 전체 통합 QA는 #220·#221에서 추적한다.

## 계약

서버 API 계약·권한을 변경하지 않는다. 기존 `POST /auth/admin/login`, `POST /auth/login`, `POST /auth/token/refresh`, `POST /auth/logout`을 사용한다. 복귀 경로 판단은 로그인 후 서버가 반환한 사용자 ID와 역할을 사용하며 서버의 실제 접근 권한 검사도 계속 적용된다.
