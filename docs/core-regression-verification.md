# 핵심 회귀 테스트 검증

## 실행

```sh
npm ci
npm test
npm run lint
npm run build
npm run test:regression-history
```

Node.js와 Git, tar 및 저장소의 과거 커밋 이력이 필요합니다. 얕은 clone에서는
먼저 필요한 이력을 가져오세요. 운영 계정, 토큰, 서버 접속은 사용하지 않습니다.

`npm test`는 현재 작업 파일 전체를 검증합니다. `test:regression-history`는
**커밋된 HEAD**를 기준으로 비교하므로, 미커밋 제품 코드 변경은 반영하지 않습니다.
스크립트·실행 명령·문서만 변경한 경우에는 제품 코드가 동일한 HEAD 비교가 유효합니다.

## 비교 방식

- HEAD를 `git archive`로 OS 임시 디렉터리에 복사합니다. 각 실행은 별도 디렉터리입니다.
- 현재 테스트·의존성을 유지하고, 수정 전 비교에서는 지정한 제품 파일만 과거 버전으로 교체합니다.
- 따라서 과거 릴리스 전체의 재현이 아니라 **해당 수정의 효과를 분리한 비교**입니다.
- node_modules는 현재 설치를 링크하여 사용합니다. 소스와 Git 작업트리는 변경하지 않습니다.
- 각 대상은 이름으로 지정한 실제 테스트를 실행합니다. 현재 통과와 과거 assertion 실패가 모두 필요합니다.
- 테스트 누락, import/빌드 오류, 시간 초과, 프로세스 종료는 재현 성공이 아닙니다.
- Node TAP이 오류 객체 비교 assertion을 ERR_TEST_FAILURE로 직렬화하는 #152는
  해당 테스트의 reference-equal 실패와 실제 401/기대 500 차이를 함께 확인합니다.
- 실행 제한은 테스트당 30초이며 정상·실패 종료 시 생성한 임시 디렉터리를 제거합니다.
  강제 종료(SIGKILL 등) 시에는 OS 임시 디렉터리에 잔여 파일이 남을 수 있습니다.

## 범위

검증 기록 (2026-09-15): 제품 코드 `fb516bdc13479cf08292de4e18f682f23294f1ee` 기준으로
13개 현재 실행 통과, 13개 수정 전 실행에서 지정된 assertion 실패를 확인했습니다.
`npm test` 전체 193개, lint, build, `git diff --check`도 통과했습니다.

이 비교는 9개 이슈의 대표 동작 13개를 검증합니다. 전체 테스트의 모든 분기를
과거 코드에서 실패시킨다는 의미는 아닙니다. 다른 입력·실패·복구 분기는 `npm test`로
확인합니다. 실제 브라우저, 운영 API, 배포 완료 검증을 대체하지 않습니다.

앞으로 제품 동작이나 테스트가 바뀌어 비교가 실패하면 무조건 성공 판정 조건을
넓히지 말고, 해당 테스트가 실행됐는지와 실패 원인을 먼저 확인하세요.
