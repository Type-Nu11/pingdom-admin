# 상점주 처리 모달 안전성·접근성 (#270)

## 적용 범위

- 결제 전액 환불, Verified Boost 상품 선택·집행 중단, 장소 정보 재확인 응답, 리뷰 삭제 요청의 5개 모달을 기존 `AppDialog`로 연결했다.
- 처리 중 X·배경·Escape·취소/닫기는 모두 차단한다. 비활성 배경 클릭으로 페이지에 포커스가 빠지지 않도록 기본 동작도 차단한다.
- 초기 포커스, Tab/Shift+Tab 순환, Escape 닫기, 접근 가능한 제목·설명을 공통으로 사용한다. 중첩 모달의 Escape가 상위 모달까지 닫지 않도록 전파를 차단한다.
- 성공 후 원래 버튼이 사라지거나 비활성화되면 페이지 제목으로 포커스를 복원한다. 취소 시 원래 버튼이 유효하면 그 버튼으로 돌아간다.
- 처리 실패는 모달 내부에서 안내하며 대상·입력·선택을 보존한다. 대상 화면의 처리 오류는 5초 뒤 자동으로 사라지지 않는다. 재시도 또는 새 모달을 열 때 초기화하며, 성공 안내와 다른 화면의 기본 자동 닫힘 정책은 유지한다.
- 본문 스크롤과 하단 동작 영역을 분리한다. 폼 밖의 제출 버튼은 고유 `form` ID로 연결한다.

기존 요청 잠금, 상품 선택의 재시도 idempotency key, 인증·권한 판단, API URL·본문·환불 정책은 변경하지 않았다.

## 자동 검증

`node --test tests/merchant-dialog-safety.test.mjs`

실제 페이지와 훅을 JSDOM에서 렌더링하고 Axios adapter로 합성 응답을 제공한다. 실계정이나 실서버를 사용하지 않는다.

- 각 모달의 제목·설명·초기 포커스·키보드 순환·Escape 복원
- 지연 요청 중 모든 닫기 경로 차단, 중복 제출 1회 제한
- 500 실패 후 입력/대상 보존 및 재시도 성공, 성공 후 대체 포커스
- 오류 자동 닫힘 타이머 미등록, 새 모달에서 이전 오류 초기화
- 환불 401/403/409 구분 및 기존 인증 해제 정책 유지
- 상품·장소·사유 및 재시도 idempotency key 보존
- 중첩 모달의 Escape 전파 방지

## 브라우저 검증

`node tests/browser/merchant-dialog-server.mjs`

별도 임시 포트의 출력 URL에 아래 쿼리를 사용한다. 사용자 개발 서버의 포트나 데이터를 변경하지 않는다.

- `screen=refund|review|response|selection|stop`
- `scenario=success`: 합성 처리 성공
- `scenario=error`: 합성 500 실패
- `scenario=delayed`: 첫 제출이 12초 후 합성 500 실패, 이후 재시도 성공

이 fixture는 실제 컴포넌트·훅을 사용하되 모든 Axios 요청을 합성 adapter에서 처리한다. 지정되지 않은 요청은 차단하며 실서버로 전달하지 않는다. 화면의 변경 요청 횟수로 제출 수를 확인할 수 있다. fixture의 성공은 서버에서 실제 업무가 처리됐다는 뜻이 아니다.

Codex 인앱 Chromium에서 확인한 내용:

- 1920×1080: 환불·리뷰 요청 처리 중 Escape 차단, 환불 배경 클릭 후 모달 포커스 유지, 실패 후 대상/입력·오류 보존 및 재시도 완료
- 재확인 응답: 실패 후 응답 내용 유지, 정상 제출 후 목록 갱신과 페이지 제목 포커스
- 상품 선택·중단: Tab/Shift+Tab 순환, Escape 취소 후 원래 버튼 복원, 정상 처리 후 목록 갱신과 유효한 위치로 포커스 복원
- 1366×768: 긴 상품 설명과 버튼 배치 확인
- 390×844: 상품 선택 폼의 세로 배치, 본문 스크롤, 하단 버튼 노출과 키보드 순환 확인
- 정상 상품 선택·중단 검증 탭에서 콘솔 error/warn 없음. 실패 fixture의 합성 오류는 의도된 테스트 결과다.
