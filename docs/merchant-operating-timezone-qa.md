# 상점주 영업 확인 시각 표시 검증 (#253)

## 계약 및 변경

- 2026-10-01 공개 `/v3/api-docs/merchant`의 `MerchantOwnerOperatingResponse.checkedAt`, `PlaceOperatingNoticeListResponse.checkedAt` 설명에서 UTC 기준임을 확인했습니다.
- 시간대 없는 ISO 날짜·시각은 이 두 응답에서만 UTC로 해석합니다. Z 또는 offset이 있으면 그 값을 그대로 해석한 뒤 Asia/Seoul로 표시합니다.
- 한국 시각과 KST를 명시하고, `<time>`의 datetime에는 UTC ISO 값을 사용합니다. 소수 초는 최대 9자리 입력을 받아 밀리초까지만 파싱합니다.
- 빈 값·잘못된 날짜·시각은 '확인 시각 정보 없음'으로 표시합니다. 영업 여부는 서버 응답을 그대로 사용하고 로딩·실패 상태에는 확인 시각을 표시하지 않습니다.
- 다른 LocalDateTime 필드 및 API 요청·응답 형식은 변경하지 않았습니다.

## 검증

- 자동 테스트: UTC→KST, 날짜·연도 변경, 자정, 윤년, Z/양수·음수 offset, 소수 초, null/invalid 및 날짜 정규화 방지.
- 컴포넌트: true/false 상태 유지, 정규화된 datetime 및 시각 정보 없음 표시.
- Playwright: 실제 운영 정보·운영 공지 페이지에 모의 GET 응답을 주입하여 1920×1080·1366×768에서 확인했습니다. 브라우저 시간대는 America/Los_Angeles이며 두 화면 모두 KST로 표시됩니다.
- 확인 시각의 컨테이너 내 배치, 가로 넘침 없음, 실패 후 키보드 재시도, 미처리 JavaScript 오류 없음을 확인했습니다. 대표 스크린샷도 시각적으로 확인했습니다.
- 브라우저 검증의 Vite 캐시는 임시 경로로 분리합니다. 테스트 종료 시 서버·브라우저는 finally에서 닫습니다.

## 한계

- 공개 Swagger는 실서버에서 읽었지만, 로그인한 실계정의 운영 API 응답은 이번 작업에서 조회하지 않았습니다.
- 영업 일정·상태·공지 등록 등 실제 데이터를 변경하는 요청은 수행하지 않았습니다. 전체 통합 QA는 #220에서 추적합니다.
