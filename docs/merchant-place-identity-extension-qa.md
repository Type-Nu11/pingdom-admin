# 인증 부스트·정보 재확인 매장 식별 QA (#271)

## 구현 범위

- 인증 부스트: 상품 적용 장소 선택, 선택·집행 목록, 중단 확인에 매장명·주소와 보조 ID를 표시한다.
- 정보 재확인: 요청 목록과 응답 모달에 같은 대상 매장의 이름·주소·ID를 표시한다. 요청 ID는 별도로 유지한다.
- 기존 `MerchantPlaceProvider`/`useMerchantPlaceIdentity` 캐시와 `MerchantPlaceSelect`를 재사용한다. 반복되는 목록·모달 표시는 조회를 수행하지 않는 공통 컴포넌트에 맡긴다.
- 장소 선택기의 기본 폭은 유지하고, 부스트 모달에서만 전체 폭과 선택한 매장의 전체 이름 표시를 사용한다. 긴 후보 이름·주소는 줄바꿈한다.
- 조회 중과 상세 실패를 구분하고, 실패 시 ID와 권한·연결 상태 확인 안내 및 재조회 버튼을 제공한다. 임의 이름을 생성하지 않는다.
- 부스트 프로필에서 빠진 장소는 과거 기록에서 현재 관리 장소 목록에 없음을 안내한다. 새 상품 선택 후보는 기존대로 프로필의 연결 장소 ID만 사용한다.

## 보존한 계약

- 상품 선택은 `productId`/`placeId`/`idempotencyKey`, 시작은 `selectionId`, 중단은 `executionId`, 재확인 응답은 `requestId`/`responseNote`를 그대로 사용한다.
- 표시 이름은 권한 판단에 사용하지 않는다. 인증·권한 오류 처리와 서버의 최종 검사를 우회하지 않는다.
- 처리 중 닫기·입력·중복 제출 잠금, 선택 실패 시 멱등 키 유지, 응답 미저장 보호를 유지한다.

```sh

node tests/browser/merchant-identity-extension.mjs
node tests/browser/merchant-place-select.mjs
```

- 신규 화면 회귀: 0/1/여러 장소, 같은 이름과 다른 주소, 부분 상세 실패·재조회, 늦은 상세 응답과 열린 모달의 ID 유지, 연결 해제·404, 화면 간 캐시 재사용, 계정 전환 시 이전 상세 응답 폐기.
- 합성 변경 요청으로 표시 대상과 상품 선택·집행 시작·중단·응답 제출의 실제 전송 ID를 대조한다. 상품 선택·응답 제출의 처리 중 잠금도 검증한다.
- 기존 캐시 테스트에서 StrictMode, 401/403/404/500 정책, 요청 중복 억제와 이전 계정의 응답 무시를 재검증한다. 기존 모달 검사에서 처리 실패·재시도·멱등 키·포커스 동작을 재검증한다.
- 실제 Router와 MerchantLayout을 사용한 Chromium 브라우저 QA: 1920×1080, 1366×768, 390×844. 긴 이름·주소 줄바꿈, 모달·후보 목록의 가로 넘침, 키보드 선택·Escape, 화면 왕복 시 중복 조회 없음, 빈 목록·재조회, 응답 작성 취소 시 입력 보호를 확인한다.
- 브라우저 어댑터는 모든 변경 요청을 금지하며 실서버로 전달하지 않는다. 자동화 브라우저에서도 `/api` 요청을 차단한다.

## 검증 한계

- 위 검사는 계약 모양의 합성 데이터로 수행한 웹 회귀 검사다. 실계정·실제 서버 권한 변경·실기기·운영 배포 QA를 완료했다고 해석하지 않는다. 전체 상점주 QA는 #220에서 추적한다.
- 매장 이름·주소 캐시는 로그인 세션 단위다. 외부에서 바뀐 이름·권한을 실시간 감지하는 API나 구독은 추가하지 않았다. 최신 프로필에 없는 장소는 안내하지만, 이미 캐시된 이름 자체는 역사적 기록의 식별용으로 남을 수 있다.
- 상세 API가 권한 부족·연결 해제 등으로 실패하면 이름·주소를 확보할 수 없으므로 ID와 실패 안내를 유지한다. 웹에서 가짜 장소명으로 대체하지 않는다.
- 승인·집행·중단·응답 등 실제 운영 상태는 변경하지 않았다. 운영 자격 증명과 개인 데이터도 사용하지 않았다.
