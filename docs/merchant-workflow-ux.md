# 상점주 업무 이동 UX

- 관련 이슈: https://github.com/Type-Nu11/pingdom-admin/issues/247
- 검증일: 2026-10-02

## 작업 통합

`개발2`의 `PingDom_Web_2` 작업트리, `fix/merchant-workflow-accessibility` 브랜치에 있는 미커밋 변경과 비교하여 통합했다. 두 브랜치의 기준 커밋은 `304e611fc5940c2ce039aec662f541107520b690`으로 동일했다. 원본 작업트리는 수정하지 않았으며 통합 작업 위치는 `PingDom_Web`의 `refactor/merchant-workflow-ux`다.

- 공통 변경인 내역 우선 진입, 새 신청 분리, 쿠폰 바로가기, 성과 하단 배치는 중복 구현하지 않고 하나로 유지한다.
- 개발2의 상태별 혜택 안내 문구, 명확한 쿠폰 이동 버튼명, 이벤트 바로가기를 반영한다.
- 개발2에서 보강한 첨부 초안 저장·제출, 혜택 목록·페이지 이동·매장 전환, 내역 이동의 미저장 보호 테스트를 가져온다.
- 이 대화의 상세 조회 성공 후 화면 전환, 양방향 화면 포커스, 쿠폰 입력란 직접 포커스, 홈 입력 보호 및 모바일 배치 보완을 유지한다.
- 브라우저 테스트의 포커스 대상과 홈 링크 개수는 최종 통합 구현에 맞춰 변경했다. 원본 QA 문서는 중복 생성하지 않고 이 문서에 통합 검증 결과를 기록한다.

## 변경 범위

### 신규 장소 등록

- 최초 진입 화면은 신청 내역이다. 긴 신청서 아래로 내려가지 않고 기존 신청을 선택한다.
- 신청 내역과 신청서 중 한 화면만 표시한다. 새 장소 등록 신청은 별도의 빈 신청서를 연다.
- 조회 중 상태와 실제 빈 목록을 구분한다. 최초 조회 중에는 새 신청서 진입을 비활성화한다.
- 기존 신청 상세 조회가 성공해야 신청서를 연다. 실패하면 목록과 오류를 유지한다.
- 화면 전환 시 새 화면 시작 지점으로 스크롤하고 포커스를 옮긴다.
- 입력이나 업로드 대기 파일이 있으면 기존 미저장 변경 확인을 거친다. 이동 취소 시 그대로 유지한다.
- 이동을 확정하면 로컬 미저장 입력과 대기 파일을 버린다. 서버에 저장된 신청서는 삭제하지 않는다.
- 신청 취소 성공 시 내역으로 돌아간다. 취소 내역 탭과 같은 신청 다시 열기도 유지한다.
- 모바일에서는 내역 제목과 탭을 줄을 나누어 배치한다.

### 혜택과 쿠폰

- 상단 쿠폰 사용 버튼은 기존 쿠폰 코드 입력란으로 스크롤하고 포커스만 옮긴다.
- 바로가기는 사용 처리 요청을 보내거나 혜택 선택, 작성 내용, 쿠폰 코드를 초기화하지 않는다.
- 기존 코드 검증과 최종 사용 확인을 유지한다. 처리 실패 시 코드를 유지하고 성공 시 초기화한다.
- 혜택 상세 안내는 초안 공개, 공개 혜택 종료, 종료 혜택 조회 등 상태에 맞는 내용으로 바꾼다.
- 서버에서 지원하지 않는 혜택 수정이나 삭제 기능은 추가하지 않는다.

### 내 가게

- 운영 정보, 메뉴, 리뷰, 이벤트, 예약 설정, 예약 내역, 혜택·쿠폰의 바로가기를 상단에 둔다.
- 기존 운영 요약은 유지하되 높이를 줄이고 전체 매장 성과를 기본 정보 및 운영 목록 아래로 옮긴다.
- 성과는 기존 API의 전체 연결 장소·기간 제한 없는 집계다. 선택 장소 성과나 오늘의 성과로 바꾸지 않는다.
- 실제 장소명과 주소를 표시하는 기존 장소 선택 UX를 유지한다.
- 기본 정보 입력도 공통 미저장 변경 보호에 연결한다. 바로가기 및 장소 변경 취소 시 입력을 유지한다.

신규 브라우저 테스트는 실제 Router와 페이지를 사용한다. API 응답은 합성 데이터이며 외부 API 요청을 차단한다. 합성 쿠폰 사용 처리 외의 변경 요청은 테스트 실패로 처리한다.

신청 30건, 취소 내역, 빈 목록, 느린 조회, 목록·상세 500, 인증 실패, 같은 신청 다시 열기, 새 신청 초기화, 대기 파일 유지·폐기, 키보드 진입과 포커스를 검증했다. 쿠폰 바로가기·확인 취소 시 요청이 없는지, 합성 사용 처리 실패·재시도·성공과 세 혜택 상태 안내를 확인했다. 홈의 업무 우선 배치 및 기본 정보 입력 중 이동 취소도 검증했다.

## 제한

- Chromium 합성 데이터 검증이다. 실제 서버의 심사 요청이나 실제 쿠폰 사용은 수행하지 않았다.
- API 계약과 서버 코드는 변경하지 않았다.
- Safari·Firefox 및 전체 상점주 QA 이슈의 모든 항목을 검증한 것은 아니다.
