# 장소 상세 브라우저 검증 (#172)

## 실행

```sh
npm ci
npx playwright install chromium
npm run test:place-inspector-browser
```

비교용 Git 객체 `f09c4cb9135d6b9ac949eeb31f3dbf0424d15d7f`가 필요하다.
얕은 복제라면 해당 이력을 먼저 가져온다. 기준 코드를 읽을 수 없으면 검증은 실패한다.
임시 포트의 서버와 브라우저는 성공·실패 시 모두 종료한다.
화면 캡처 경로는 실행 로그에 출력한다.

## 비교 조건과 결과

2026-09-15 Chromium에서 동일 합성 장소·이미지와 현재 장소 관리 페이지를 사용했다.
개선 전은 PR #190 이전 커밋의 `PlaceInspector.tsx`만 교체하여 렌더링했다.
페이지 셸과 공통 스타일은 양쪽 모두 현재 버전이므로 과거 배포 전체를 재현한 비교는 아니다.

영업시간 수정 버튼 전체가 상세 본문 안에 보이기까지 필요한 최소 내부 스크롤(px):

| 화면 | 개선 전 | 현재 |
| --- | ---: | ---: |
| 1280×800 | 335 | 0 |
| 1280×600 | 535 | 0 |
| 390×800 | 551 | 0 |
| 390×600 | 551 | 0 |

측정은 상세에 진입한 후 본문 스크롤을 0으로 놓고 버튼 하단과 본문 하단의 차이를 계산한다.
모바일은 목록 아래 지도·상세까지 페이지를 스크롤해야 한다. 표의 0은 페이지 전체의
스크롤이 없다는 뜻이 아니다. 모바일 지도 영역 최소 높이 때문에 두 높이의 내부 측정값이 같다.
운영 상태·탐색 노출 상태는 영업시간보다 위에 표시된다.

## 회귀 검증

- 실제 PlaceManagePage, 목록·상세·운영 패널·삭제 확인창을 렌더링
- 목록 선택 후 상세 조회와 지도 대상 연동
- 위치 보기 콜백에 선택한 장소의 좌표가 전달됨
- 대표 이미지 확대·Escape 닫기·포커스 복귀 및 이미지 로드 확인
- 영업시간 수정창 진입·Escape 닫기
- 기술 정보 펼치기 및 대상 전환 후 접기 초기화
- 삭제 ID 미입력·오입력 차단, 올바른 ID 입력 시 활성화, 취소
- 지도 모의 마커로 두 번째 장소 선택, 목록 선택 상태 연동
- 긴 장소명과 이미지 404 대체 표시, 패널·페이지 가로 넘침 없음
- 브라우저 예외 없음, 변경 요청 없음

API는 허용한 목록·상세 GET에만 합성 응답을 제공하고 나머지 요청은 실패시킨다.
지도 SDK는 모의 컴포넌트로 교체하며 실제 지도 타일·마커 배치·SDK 동작은 검증하지 않는다.
브라우저의 실제 API·외부 요청도 차단하며 UI 폰트 CDN만 허용한다.
실제 계정·장소·개인정보는 사용하지 않고 삭제·상태 변경을 실행하지 않는다.

전체 단위 테스트 288개, lint, build 통과. 제품 코드 변경 없이 기존 #190 개선을 검증한다.
실서버 권한·데이터 정합성, 실제 Kakao 지도, Safari/Firefox, 운영 배포는 미검증이다.
따라서 실서버·지도 SDK 전체 통합 검증까지 완료했다고 해석하지 않는다.
