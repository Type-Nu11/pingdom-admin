# 미저장 작성 폼 보호 (#243, #274)

등록된 보호 상태가 있는 동안 사이드바·일반 링크 이동과 브라우저 뒤로/앞으로 가기는 공통 확인창을 사용한다. 모든 기존 폼을 일괄 보호하는 변경은 아니다. 다른 운영 폼과 전체 통합 QA는 #220·#221에서 별도로 추적한다.

## 상태와 사용자 선택

- 최초 입력 또는 마지막 저장 성공 시점의 스냅샷과 현재 값을 비교한다. 원상 복원, 읽기 전용 폼, 변경 없는 조회는 경고하지 않는다.
- `계속 작성`은 이동을 취소하고 현재 입력을 유지한다. `변경 버리고 이동`은 요청된 이동을 한 번 실행한다. 반복 클릭은 첫 요청을 유지한다.
- 같은 화면의 항목 변경은 `useUnsavedNavigation`을 사용한다. 편집창 닫기는 `useUnsavedChanges`의 해당 폼 범위만 확인하여, 부모 폼이 변경되었다는 이유로 빈 편집창을 막지 않는다.
- 저장 중인 폼은 버리고 이동할 수 없다. 저장 성공은 기준을 갱신하고, 실패는 기준과 입력을 유지한다. 이미 차단된 경로 이동은 저장이 성공해 보호 상태가 없어지면 이어진다.
- 선택한 파일과 아직 서버에 제출하지 않은 첨부는 별도 보호 상태다. 텍스트를 저장했다는 이유로 미제출 파일까지 저장된 것으로 취급하지 않는다.
- 기존 공개·비활성화 등 업무 확인은 유지한다. 미저장 확인을 통과해도 업무 확인을 취소하면 업무 API는 호출하지 않는다.
- 새 브랜드 등록 시 이벤트 편집창을 재생성하지 않고 브랜드만 반영한다. 작성 중인 제목·소개를 보존한다.
- 메뉴 순서 변경은 API 호출 전에 미저장 확인을 거친다. 계속 작성하면 순서 변경 요청 없이 입력을 유지한다.
- 날짜·시간 선택 팝업의 Escape는 가장 안쪽 팝업만 닫고 해당 버튼으로 포커스를 돌린다. 달력이 열려 있다는 이유로 부모 편집창의 미저장 확인을 띄우지 않는다.

## 라우터와 인증

`Router`를 기존 경로·권한·레이아웃을 유지한 데이터 라우터로 전환하여 React Router의 `useBlocker`를 사용한다. 공통 Provider는 입력 값이나 파일을 저장하지 않고 폼 ID와 dirty/busy 플래그만 보관한다.

로그인 경로 이동은 차단하지 않는다. 기존 AuthProvider의 계정·역할·세션 경계에서 하위 트리가 재생성되므로 로그아웃·인증 만료·계정 전환 후 이전 폼과 확인창이 남지 않는다. 민감한 입력의 localStorage/sessionStorage 저장이나 자동 복원은 추가하지 않았다.

브라우저 새로고침·탭 닫기는 dirty/busy일 때만 `beforeunload`를 등록한다. 앱 확인창으로 대체할 수 없고 문구도 브라우저가 결정한다. 사용자 상호작용 조건, 모바일 프로세스 종료 등 브라우저가 경고를 제공하지 않는 경우까지 데이터 보존을 보장하지 않는다.

## 입력 안내

상점주 메뉴·이벤트·브랜드·장소 신청의 필수/선택 항목을 표시했다. 기존 관리자 필수 표시, 필드 검증, API 오류 및 저장 중 상태는 유지했다. 장소 신청의 연락처 예시는 국가번호를 포함한 한국 번호로 정리했으며, 기존 정규화·국가 지원·API payload 규칙은 변경하지 않았다.

## #274 보완 및 검증 (2026-10-06)

- 단순 공지 목록 필터나 가격·취소 조건 창 열기는 작성 폼을 교체하지 않으므로 경고하지 않는다. 가격·취소 조건의 기존 보호는 유지한다.
- 같은 항목·매장 재선택은 경고하지 않는다. `새 시간`·`새 공지`는 신규 폼을 작성 중이어도 명시적인 초기화로 처리한다.
- 수동 새로고침은 동의한 뒤 조회하며, 성공한 결과만 새 기준으로 삼는다. 조회 실패 시 이전 입력을 유지하고 오류를 표시한다. 조회 실패를 저장 중으로 취급해 이동을 영구 차단하지 않는다.
- 운영 정보의 조회 시각을 영업시간 폼 key로 쓰지 않는다. 상태 저장·미디어 후속 조회가 다른 영업시간 초안을 지우지 않는다. 재조회 동안 오래된 현재 영업 여부·확인 시각은 표시하지 않으며, 실패 후 시간 저장은 재조회 성공 전까지 막는다.
- 영업시간 비교에서는 렌더링용 행 ID를 제외한다. 저장 성공한 상품 폼은 상품명만 비우고 상품 유형은 유지하며, 그 초기화 결과를 새 기준으로 기록한다.
- 공지 취소 사유·재확인 응답의 확인창은 해당 폼만 보호한다. 취소 사유만 버릴 때 뒤의 공지 입력은 유지한다. 바깥 모달의 busy 잠금과 안쪽 확인창의 Escape·포커스 복귀를 유지한다.

## #295 예약 상품 종료에 따른 후속 정리 (2026-10-18)

위 #274의 상품 폼·상품 지연 조회 검증은 당시 계약 기준의 과거 기록이다. 서버 PR #1793의 상품 제거에 맞춰 예약 상품 전용 화면·훅·API·메뉴를 제거했고, 해당 폼만을 대상으로 하는 회귀도 제거했다. 기존 미저장 보호를 완화한 것이 아니다.

- 예전 `/merchant/reservations/products` URL은 기존 상점주 권한 검사 안에서 예약 가능 시간 화면으로 이동하고 기능 종료 안내를 표시한다. 로그인 복귀 경로 허용 목록에는 이 이전 URL을 유지해 재로그인 뒤에도 같은 안내 이동을 거치게 한다.
- 예약 시간 편집은 상품 조회 없이 작동한다. 상품 연결/유형 필드는 입력·초안·슬롯 타입·등록/수정 요청에서 제거했다. API 경계에서도 해당 필드가 들어온 구형 요청(null 포함)은 전송 전에 거절하며, 상품 예약을 조용히 일반 슬롯으로 바꾸지 않는다.
- 예약 신청 조회의 공유 상품 API 호출도 제거했다. 예약 confirmation의 가격/상품 표시 전체 정리는 #297에서 별도로 진행한다.
- 슬롯의 조회 실패(401/403/500), 재시도, 조회 중 저장 차단, 요청 역전, 미저장 입력의 계속 작성/버리고 이동, 저장 실패 입력 유지, 계정·세션 전환과 중복 제출 보호를 검증했다.
- 새 브라우저 검증은 실제 `Router`, 상점주 레이아웃과 보호 경로를 사용한다. 업무 API는 인메모리 어댑터로만 처리하며, `.env`·개발 프록시를 읽지 않는 격리 Vite 서버와 네트워크 차단을 사용한다. 시연 폰트 외 운영 API 요청은 허용하지 않는다.
